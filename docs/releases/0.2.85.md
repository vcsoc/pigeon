# Pigeon 0.2.85 — prompt file discovery and incremental rescans

- Filesystem changes scan the changed directory (or the common parent of a burst), not invariably the whole indexed root. Local events are coalesced for 250 ms. Events during managed filesystem operations are deferred instead of discarded; network debounce and access timeouts remain conservative.
- Rescan retries missing/failed previews and regenerates changed files, without rebuilding valid cached previews. Explicit **Rebuild Thumbnails** remains available. Rescan updates are incremental, without a full portfolio reload.
- Pending rescans retain distinct requested subtrees and merge repeated requests. Follow-up requests are consumed after cleanup, not captured before asynchronous work.
- Metadata scans release their scan lock independently of preview completion. Successive scans share bounded per-location preview workers, with per-asset serialization and explicit retries of completed failures. Background preview work remains visible in Threads; hashing/backups wait for it.
- Local scan content hashing is deferred. Preview and fingerprint completions reconcile with the current asset record, preserving newer metadata and rejecting changed, removed, or locked targets. Unchanged scan metadata retains fingerprints computed concurrently.

## Validation

573 passing component tests, including controlled preview backlogs, bounded concurrency, cancellation, same-version retries, queued subtrees, late requests, and concurrent preview/hash record replacement. Linux/Windows builds pass 39-file packaged integrity checks; Windows ZIP validation and the Linux empty-profile startup smoke pass.

Real file saves in isolated Electron, with a 3,000-image fixture and a selected 30-image subfolder:

- Automatic detection and displayed thumbnail: **556 ms**.
- Native right-click → Edit & maintain → Rescan folder: **529 ms**.
- Both retained the existing cached thumbnail's inode/mtime and portfolio stream generation. The new preview and independently verified SHA-256 persisted in SQLite.
- Existing 350-image excluded-view save regression: zero grid renders/mutations, retained card/image identity and geometry; matching-addition positive control passed.

These are local Linux results, not certification of a flat 40k directory, SMB latency/reconnect, every RAW decoder, native Windows, or macOS. The previous large-library startup and 3,000-image whole-root scan timing gaps remain open. Controlled backlog tests are component tests, not native slow-decoder timing evidence.

GitNexus reports critical scan/inspector/idle-guard impacts. Hash timer callers and newly added modules are unresolved by the existing graph; direct call-site review and tests supplement it. The current default GitNexus runner has an incompatible storage version; analysis used the compatible cached runner.

This is a prerelease. Build, installation, and GitHub publication are separate statuses; binary uploads can exceed the 15-second command limit.
