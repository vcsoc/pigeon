# Pigeon 0.3.17 — immediate manual analysis and idle-only automation

## Semantic analysis

- **Analyze now** and **Continue** start immediately. Neither free RAM, machine CPU activity nor the automatic idle timer is a condition for starting manual work.
- Automatic analysis starts only after **10 minutes of computer inactivity** by default. Change this to 1–240 minutes in **Preferences → AI Search**. Using the computer pauses automatic analysis; it resumes after the configured idle period.
- The resource slider caps actual worker CPU and memory use in both modes. It is not a free-memory reservation or admission threshold. Manual requests no longer disable future automatic idle gating.
- macOS and Windows now measure the worker's real process-tree CPU/RSS rather than using Linux-only accounting. CPU use is throttled; exceeding the actual memory cap stops the worker with an instruction to raise Resource limit and retry. Linux retains kernel CPU/memory caps.
- Memory-aware extraction and embedding microbatches also use cross-platform actual RSS.
- Saved vectors, interrupted scopes, file checkpoints and portfolio isolation are preserved. Long inactivity/user pauses defer the operation watchdog rather than causing a ten-minute timeout; genuinely stalled active work still times out.

## Feedback and reliability

- An always-visible activity card shows starting/setup/download activity, current files, scopes, queued work, progress, pauses, completion and errors.
- The resource-policy explanation is a keyboard-accessible **? tooltip** beside **Activities & technical details**, rather than an inline paragraph.
- Fixed a pre-existing collection-extraction race: archive data is held until its destination stream is ready, preventing empty imported files. A delayed-directory regression test verifies every extracted payload byte.

## Validation and distribution

- Full JavaScript/native test suite, native Python engine persistence checks, real macOS resource accounting/throttling, and Electron feedback/preferences checks are run before publication.
- Packaged integrity verifies 80 critical runtime files, including the unpacked resource monitor; packaged startup is checked separately.
- Windows/Linux artifacts retain their existing CI distribution process.
- The universal macOS package is signed with the existing **Apple Development** identity matching this installation, enabling built-in updates from the installed development-signed versions. It is **not Developer ID signed or notarized**. The production macOS CI signing/notarization gate remains unchanged.
- Dependencies are unchanged. Existing dependency audit findings are not addressed by this release. Portfolio data, model caches, screenshots/annotations and local agent files are not bundled or committed.
