# Pigeon 0.3.10 — precise crop selection

- Image-editor crop coordinate handling is corrected for rotation and flips. Fixture-based pixel regressions cover all four quarter-turns and both flip states; tests also confirm Apply crop does not overwrite the original. The specific user-reported image still needs a retry before its defect can be called resolved.
- The dashed crop rectangle has eight draggable points (corners and edge midpoints) for resizing. Drag its interior to move it within image bounds.
- Small green ✓ and red × controls next to the marked area apply or cancel just the crop. Enter also applies; Escape cancels the active crop without closing the editor. Applying keeps the editor open with the new cropped preview. Save continues to write the supported original file; Save copy and Save draft keep their existing behaviors.
- Short clicks/drags and one-pixel selections cannot become crop drafts; invalid or out-of-bounds crop coordinates fail safely rather than silently clamping into a thin line. A thumbnail-only or reduced-resolution proxy cannot be used for a crop without warning; reconnect the full-resolution source first. The editor measures the decoded image before allowing coordinates to be selected.
- Resize image is now a separate toolbar icon with a tooltip. It starts inactive; changing image dimensions requires explicitly selecting it, and selecting it again cancels pending resize changes. Save without Resize retains source dimensions in isolated image tests. Crop, rotation, and explicit AI enlargement still change output geometry when chosen.
- Crop controls stay legible over a rotated/flipped image, and the earlier double-Escape preference remains unchanged.

Local native and packaged tests cover dragging, accidental slivers, thumbnail-only sources, canceling, applying, pixel matching, rotated crops, reopening, and source-file preservation. Existing distribution and CPU/GPU limitations remain unchanged.
