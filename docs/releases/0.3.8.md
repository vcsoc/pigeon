# Pigeon 0.3.8 — reduce non-AI background CPU spikes

- Opening the default Duplicates category now uses indexed **exact** duplicates only; it does not silently start a library-wide visual similarity comparison. “Find similar” and scoped similarity actions still work explicitly. Leaving the view cancels an active comparison, including a sleeping worker.
- Similarity and fingerprint workers measure their own CPU time and cooperatively sleep around an 8% one-core duty target, including worker startup where supported. Comparison checkpoints cover hash buckets, tree searches, no-hash fallbacks and single-source matching, preserving results and progress.
- Index scans now use one worker and an 8% worker duty target instead of four workers and a 20% target. Background fingerprinting and explicit thumbnail rebuilding use one worker; scan preview concurrency is one. Before starting another indexing/preview job, Pigeon defers while Electron process CPU is already at or above 8%.
- Fixed a sidebar Smart Folder count cycle that recomputed the entire library every time the count repainted the sidebar. Valid counts now settle until asset/folder invalidation; the Smart Folder rule-dialog counter has its own timer and cannot interrupt sidebar counting.
- Diagnostics now distinguish **GPU-process CPU** from actual GPU utilization; Electron does not expose reliable cross-platform GPU utilization or a GPU work quota. Hardware acceleration preferences, AI processing, originals and metadata are unchanged.

Native evidence: a populated installed portfolio previously used 19–23% of one core during five idle one-second samples, mostly in the renderer. After the sidebar count fix and startup processing settled, eight consecutive one-second samples showed 0% CPU across installed processes; an earlier startup interval still reached 22%. This is not universal or cold-start certification.

**Important limitation:** 8% is a cooperative non-AI background target measured in units of one logical CPU, not a hard guarantee of 10–12% combined CPU/GPU for the whole application. Sharp, ffmpeg, Chromium rendering, user-initiated foreground work, operating-system scheduling and GPU drivers can exceed it briefly. A strict aggregate GPU ceiling is not available from Electron; a strict system-wide CPU ceiling requires OS resource controls and would trade away interaction and scan latency. Large cold-library scan/preview throughput may decrease; previous speed budgets must be remeasured rather than assumed passed.
